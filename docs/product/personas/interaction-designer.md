# Quinn, interaction designer

<!-- Stories link to a section, for example persona-interaction-designer#goals. -->

## Goals

- Define what a guest can do, how they move and what responds to them, in a form that others can review.
- Try an interaction in a playable prototype with placeholder art, before final assets exist.
- Design an interaction once and see how it maps to each target's input.
- Reuse proven interaction patterns from earlier projects rather than rebuild them.
- Check comfort and clarity with real people, and see the changes that result.

## Skills and tools

- Interaction, game or experience design for headsets, screens and touch **[assumed]**.
- Unreal Engine, usually through Blueprint and the editor **[assumed]**.
- Sketches, flow diagrams and prototypes. May direct an agent to build them **[assumed]**.
- Does not need to write C++ or use the command line **[assumed]**.

## Context of use

Works at a workstation and in a headset, moving between the Unreal Editor and trying the result. Starts early, before art is final, and returns during rehearsal and guest testing. Works with the director on intent, with Sam on implementation and with Riley on the environments that hold the interactions **[assumed]**. May be hired per project, or the role may be held by the director or a technical artist **[assumed]**.

## Frustrations

- Interaction is decided late, after environments are built, when changes are expensive **[assumed]**.
- A design that works on one device fails on another's input **[assumed]**.
- Comfort and confusion problems appear only when a new guest tries the experience **[assumed]**.
- Interactions are rebuilt for each show because nothing was saved in a reusable form **[assumed]**.
