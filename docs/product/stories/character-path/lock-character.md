# Lock a character before rehearsal

As Morgan, the director, I want to lock a character before performers rehearse with it, with later changes approved by a named person so that I keep the creative bar high and decide what changes.

## Acceptance criteria

- Morgan, or the delegate for character design, sets the point at which a character locks, before the first rehearsal with performers, and locks it there. The lock records who did it and when. An agent cannot lock or unlock a character.
- When locking, Morgan names the person who approves later changes to that character. The status board (story-review-and-status-status-board) shows each character's lock state and that person.
- After the lock, any change to the character, such as its mesh, rig, retarget, forms or materials, is a new version that waits in the review queue for the named person (story-review-and-status-hold-gated-hand-off). An agent can draft a change but cannot approve it. Until it is approved, rehearsals and show mode use the locked version.
- When a change is approved, each performer who drives the character is told what changed before their next session. Kai gets a short summary in text through their chosen notification channel (story-review-and-status-notifications), and can have it read aloud. Kai's confirmation that they have seen it is recorded with the date.
- The locked version and each later version can be compared side by side (story-review-and-status-feedback-and-versions).
